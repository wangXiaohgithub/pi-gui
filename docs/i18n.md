# pi-gui 国际化维护指南

## 支持语言

- `en`：英文，是翻译 Key 和文案含义的基准。
- `zh-CN`：简体中文。

应用首次启动时由 Electron `app.getLocale()` 提供系统 locale。`zh-CN`、`zh-SG`、
`zh-Hans` 以及其他明确的简体中文 locale 映射为 `zh-CN`；`zh-TW`、`zh-HK`、
`zh-Hant` 和非中文 locale 使用英文。用户选择保存到现有 `ui-state.json` 的
`language` 字段，切换时经 Main → Preload → Renderer 状态边界立即生效，无需重启。

## 文件位置

- 入口：`apps/desktop/src/i18n/index.ts`
- locale 解析：`apps/desktop/contracts/locale.ts`
- 英文：`apps/desktop/src/i18n/locales/en.ts`
- 简体中文：`apps/desktop/src/i18n/locales/zh-CN.ts`
- Key 对齐检查：`apps/desktop/scripts/check-i18n.ts`

## 增加文案

1. 先在 `en.ts` 中增加语义化 Key，例如 `sidebar.newThread`。
2. 在 `zh-CN.ts` 的相同位置增加中文翻译。
3. React 组件通过 `useTranslation()` 取得 `t`，不要添加
   `language === "zh-CN"` 形式的分支。
4. 运行 `pnpm check:i18n`。该命令会列出 `Missing zh-CN keys` 或只存在于中文资源的 Key。

动态文案使用 i18next 插值；数量相关文案应传入 `count` 或明确的数值变量。中文缺失时
由 i18next fallback 到英文，英文资源本身必须完整，避免界面显示 Key 字符串。

## 新增语言

1. 在 `apps/desktop/src/i18n/locales` 增加资源文件，并与英文 Key 完全对齐。
2. 扩展 `AppLanguage`、`resolveAppLanguage` 和 i18next 的 `resources`、`supportedLngs`。
3. 在“设置 → 常规 → 语言”增加选项。
4. 增加 locale 映射、切换、持久化和 fallback 测试。

## 禁止翻译的内容

不要将以下数据送入 `t()`：用户输入、Assistant/Agent 回复、工具调用输入输出、源码、
文件内容、文件名和路径、Git Diff、终端输出、命令、日志、Stack Trace、外部 API 原始错误、
Pi session JSONL。OpenAI、Anthropic、Claude、Codex、Gemini、DeepSeek、Kimi、OpenRouter、
GitHub 等品牌名称保持原文；OAuth、API Key、Token、Git、Diff、Worktree、MCP、Skills 等
技术术语按可读性保留英文或采用中英结合。
